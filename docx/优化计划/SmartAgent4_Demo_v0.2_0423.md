# 智能座舱创新产品 Demo 设计方案 v0.2

**版本**：v0.2  |  **基于项目**：SmartAgent4 (windows-compat)  |  **资源约束**：一人 / 一台服务器 / 一台笔记本 / 百炼 & 火山引擎云端 API

**目标受众**：公司高层（关注用户体验、商业价值与技术代差，不关注底层代码）

**核心策略**：摒弃纯技术视角的自嗨，将所有硬核技术（记忆系统、多智能体协同、端到端大模型）包装成**"极速响应"、"情绪共鸣"、"随口定制"**三个老板能在 3 分钟内直观感受到的用户体验跨代。

---

## 一、 整体架构：双链路并行与一键切换

为了在极短的演示时间内形成强烈的反差震撼，建议在现有的 SmartAgent4 中控屏界面（`Cockpit.tsx`）上，设计一个**"双链路并行架构"**。前端增加一个醒目的【Omni 引擎 (Beta)】Toggle 开关，通过切换开关，让老板直观感受传统车机与未来座舱之间的代差。

### 链路 A：经典分步式（开关关闭）

经典链路沿用 SmartAgent4 现有的分步处理流程。用户的语音首先经过 ASR 引擎转录为文本，然后由后端的 Supervisor Agent 进行意图分类、任务规划与多 Agent 协同处理，最后将生成的文本回复通过 TTS 引擎合成语音并播放。这条链路的优势在于支持复杂的长期记忆、多 Agent 并行协同以及可成长技能等高级功能，但存在明显的分步延迟，且无法感知用户的语气情绪。

> **数据流**：麦克风 → **Qwen3-ASR**（支持 22 种中文方言）→ 文本 → Supervisor Agent（LangGraph）→ 文本回复 → **CosyVoice 情感 TTS** → 音频播放 + 虚拟形象口型驱动

### 链路 B：端到端全模态（开关开启）

端到端链路完全绕过传统的 ASR→LLM→TTS 分步流程。用户的原始音频通过 WebSocket 直接推送给百炼的 Qwen-Omni-Realtime API，模型在内部同时完成语音理解、情绪感知、语义推理和语音生成，并以流式方式返回带有情感色彩的音频数据。当模型判断需要调用外部工具时（如导航、播放音乐），会通过 WebSocket 返回 `tool_call` 事件，前端拦截后调用后端的 MCP 工具执行接口，将结果回传给模型。

> **数据流**：麦克风 → WebSocket → **Qwen-Omni-Realtime**（音频直接进出，原生 Function Calling [1]）→ 流式音频 + 工具调用事件 → 音频播放 + 虚拟形象口型驱动 + 车机功能联动

### 双链路对比总结

| 维度 | 链路 A（经典分步式） | 链路 B（端到端全模态） |
|------|---------------------|----------------------|
| 响应延迟 | 1-3 秒（ASR+LLM+TTS 串行） | < 500ms（端到端流式） |
| 方言识别 | Qwen3-ASR 支持 22 种方言 | Omni 模型原生多语言方言 |
| 情绪感知 | 仅文本语义层面 | 直接从声学特征感知语气情绪 |
| 全双工打断 | 不支持（需等待完整回复） | 原生支持（语义打断） |
| 情感语音输出 | CosyVoice 情感 TTS（可控） | 模型原生情感语音（自然） |
| 工具调用 | Supervisor 多 Agent 协同 | Function Calling 回调 |
| 长期记忆 | 三层记忆系统（完整） | 需额外对接（当前不支持） |
| 可成长技能 | 完整支持 | 需额外对接 |

## 二、 核心 Demo 场景剧本

整个 Demo 分为**四大幕**，层层递进。每一幕聚焦一个用户能直观感受到的"代差级"体验，而非技术概念。建议总演示时间控制在 **8-10 分钟**以内。

### 第一幕：方言秒懂（约 1 分钟）

**对应产品规划方向**：海外智能化（多语种混合识别）/ 端侧大模型基础能力

**场景痛点**：传统车机的语音识别只能听懂标准普通话，一旦用户带口音或说方言，识别率断崖式下降，用户体验极差。

**演示剧本**：

演示者先用经典链路（开关关闭）演示。邀请一位说粤语或四川话的同事（或演示者自己模拟），对车机说一句方言指令，例如用粤语说："帮我搵下附近边度有靓嘢食"（帮我找一下附近哪里有好吃的）。系统使用 **Qwen3-ASR**（原生支持 22 种中文方言 [1]），屏幕上实时打出精准的普通话转写文字，并且 Agent 正确理解了意图，调用高德地图搜索附近美食并展示结果卡片。

**惊艳点**：不需要任何解释，老板一看就懂——"方言都能听懂，这比我车上的语音助手强太多了。"整个过程只需要 30 秒，但冲击力极强。

---

### 第二幕：全双工情感交流 + 虚拟形象（约 2 分钟）

**对应产品规划方向**：情感交互（萌宠/虚拟伙伴）/ 端到端语音大模型

**场景痛点**：堵车时用户本就烦躁，传统车机慢吞吞的语音播报和无法打断的死板交互，会进一步激怒用户。用户需要的不是一个"工具"，而是一个能共情的"伙伴"。

**演示剧本**：

演示者打开【Omni 引擎 (Beta)】开关，屏幕上的虚拟形象切换为使用阿里云万相数字人生成的**老板本人形象**（提前上传老板正面照片生成的 2D 数字人）。

演示者用急躁的语气（甚至带点方言）对车机说："快点快点，给我找个最近的加油站，烦死了！" 车机**没有半秒钟的停顿**，虚拟形象（老板的脸）立刻用非常温柔、安抚的语气回答："别着急，马上为您导航到前方两公里的中石化……" 车机话还没说完，演示者直接插嘴打断："不去中石化，换个中石油！" 车机**瞬间停止**上一句话，顺滑地接上："好的，中石油在右前方五公里，这就为您重新规划路线。" 同时，屏幕上直接弹出高德地图的导航卡片（后台触发了 Function Calling）。

**惊艳点**：

老板能直观感受到三个代差级的体验跨越。第一，**零延迟**——话音刚落就有回应，没有传统车机那种"嘟"一声后漫长的等待。第二，**情绪共鸣**——它听出了你的急躁，并用安抚的语气回应，而不是千篇一律的"好的，正在为您处理"。第三，**随时打断**——你可以像和真人聊天一样随时插嘴，它能瞬间理解并切换。更重要的是，老板看到自己的形象在屏幕上生动地表达情绪，代入感极强。

---

### 第三幕：车机长出"第三只眼"（约 2 分钟）

**对应产品规划方向**：车载健康管家（主动干预）/ 端侧大模型（VLM 视觉理解）

**场景痛点**：传统车机只知道系统内的数据（地图、天气），但对车外发生的真实世界一无所知。驾驶员在陌生城市遇到复杂的限行路牌，或者在狭窄路段遇到视线盲区，传统车机完全无法提供帮助。

**演示剧本**：

演示者调用笔记本摄像头（模拟车载前向摄像头），拿出一张提前打印好的极其复杂的限行路牌照片（上面写着：工作日 7:00-9:00 外地车牌限行，前方 500 米施工等），放在摄像头前。演示者随口问一句："我现在这外地牌能往前开吗？" VLM（通过百炼 `qwen-vl-max` 或 Qwen-Omni-Realtime 的视频输入能力）瞬间看懂照片中的所有文字和逻辑，结合当前时间回答："现在是早上 8 点半，您的车牌处于限行时段，建议您右转绕行。"

接着，演示者换一张照片——画面是一个停在路边的公交车，车头前方隐约露出半截自行车轮子（经典的"鬼探头"场景）。这一次无需演示者说话，系统后台的 VLM 识别到潜在危险，直接在屏幕上弹出红色警告框，并语音急促提示："注意！右前方公交车盲区可能有自行车穿出，请减速！"

**惊艳点**：

这个场景将产品规划中"健康管家/主动干预"的理念从生理层面延伸到了环境安全层面，让老板立刻明白：未来的智能座舱不仅是个娱乐平板，而是真正具备物理世界感知力的**"第三只眼"**。而且这种"看图说话"和"意图预测"能力，是传统车机的传感器融合方案完全无法实现的。

---

### 第四幕：用嘴巴"写代码"的私人助理（约 3 分钟）

**对应产品规划方向**：端侧大模型与可成长技能（Agent Reach / Skill 生态）

**场景痛点**：传统车机的"场景模式"需要用户在手机 APP 里拉拽各种复杂的"如果…就…"（IFTTT）场景卡片，设置繁琐，且内容是死板的、不可修改的。用户想要的是一个"越用越顺手"的私人助理，而不是一个出厂时千篇一律的死板系统。

**演示剧本**：

**第一步：无中生有（自然语言定义技能）**

演示者对车机说："以后每天早上 8 点，你给我播报一下马斯克的最新推文，还有 AI 行业融资的新闻，别念太长，挑重点说。" 屏幕侧边弹出一个**"技能进化引擎"透视面板**（极客风 UI），实时显示这句口语被大模型解析成了结构化的技能参数：

| 参数 | 解析结果 |
|------|---------|
| 触发条件 | 每日 08:00 AM |
| 抓取目标 1 | Twitter (X) - @elonmusk 最新推文 |
| 抓取目标 2 | 科技新闻 - AI 行业融资动态 |
| 输出偏好 | 精简总结，只说重点 |
| 输出时长 | 不超过 2 分钟 |

虚拟形象做出"认真记录"的动作，回复："好的，我已经为您创建了专属的晨间资讯播报技能。每天早上 8 点，我会为您提炼马斯克的推文和 AI 融资新闻的重点。"

**第二步：动态聚合（Agent Reach 联网抓取）**

演示者对老板说："现在我们模拟一下第二天早上 8 点，您坐进车里。" 然后点击界面上的【模拟触发：早上 8 点】按钮。车机主动开口播报，内容**不是预设的假数据**，而是 Agent 刚刚通过联网搜索能力实时抓取的最新真实新闻，并用大模型做了一次精简总结。在播报的同时，屏幕上弹出对应的新闻卡片。

**第三步：被教训后的自我修正（技能进化）**

播报完后，演示者用略带不满的语气说："这个播报声音太大了，吵得我头疼。以后早上播报的时候，音量调到 20% 就行，而且先放一首轻音乐垫底。" 虚拟形象立刻做出抱歉的表情，语气变得轻柔："抱歉吵到您了，我已经记住了。以后晨间播报音量会固定在 20%，并且先为您播放轻音乐。" 同时，侧边的"技能进化引擎"面板闪烁更新，显示之前的技能被**打上了补丁（Patch）**：

| 补丁内容 | 修改详情 |
|---------|---------|
| 新增前置动作 | 播放轻音乐（Genre: Light/Ambient） |
| 修改音量参数 | 系统音量 → 20% |

演示者再次点击【模拟触发：早上 8 点】按钮。这一次，车机先响起了轻柔的纯音乐，然后用非常轻的音量开始播报新闻。

**惊艳点**：

这个场景完美诠释了产品规划中"Agent Reach"和"可成长技能"的核心理念。老板不需要懂什么是 LangGraph 或 PromptPatch，但他能直观感受到三件事。第一，**嘴巴就是最强的编程工具**——一句话就能定义一个包含时间、人物、领域、偏好的复杂任务，彻底告别繁琐的设置菜单。第二，**内容是活的**——播报的不是预设的死数据，而是 Agent 实时联网抓取的最新信息。第三，**它能被"教训"**——不满意就骂它，它不仅能记住，还能真的改正，而且下次执行时严格遵守新规则。这种"越用越顺手"的私人助理体验，是目前市面上绝大多数车机做不到的。

## 三、 虚拟形象方案选型

虚拟形象是整个 Demo 视觉冲击力的核心。以下是三种可选方案的对比：

| 维度 | 方案 A：现有 Live2D | 方案 B：万相数字人（DVH）全链路 | 方案 C：万相数字人（DVH）音频驱动 |
|------|-------------------|-------------------------------|--------------------------------|
| 形象来源 | 二次元模型（haru） | 上传老板照片生成 2D 数字人 | 上传老板照片生成 2D 数字人 |
| 是否支持老板形象 | 不支持 | 支持 | 支持 |
| 情感表情驱动 | 已有完整映射 | 平台内置 | 需自行传入情感音频 |
| 口型同步 | 音量电平驱动（已有） | 平台内置 | 音频驱动（平台处理） |
| ASR/TTS 可替换 | 不涉及 | 不可替换（打包） | **可替换**（自定义 ASR+TTS） |
| 与 SmartAgent4 集成 | 已集成 | 需替换前端渲染层 | 需替换前端渲染层 |
| 成本 | 免费 | 7 天免费体验；后付费 0.06 元/分钟 | 端渲染 250 元/月/设备 |
| 推荐场景 | 快速演示（不要求老板形象） | 控制台内快速展示效果 | **集成到 SmartAgent4 的最佳方案** |

**推荐策略**：

如果老板形象是必须的，建议采用**方案 C（音频驱动）**。这样 SmartAgent4 全权负责 ASR（Qwen3-ASR）、LLM（Supervisor Agent）和 TTS（CosyVoice 情感合成），然后将 TTS 生成的音频流传给 DVH 的音频驱动 SDK，由 DVH 负责驱动老板形象的口型和身体动作。这种方式既保留了 SmartAgent4 的全部智能体能力，又能展示老板的真人形象。

如果老板形象不是硬性要求，保留现有的 Live2D 方案（方案 A）是最省时间的选择，可以将精力集中在其他场景的打磨上。

## 五、 落地实施优先级与排期建议

由于只有一人资源，建议按照**"投入产出比"**从高到低排列开发优先级：

| 优先级 | 任务 | 预估工时 | 产出价值 |
|--------|------|---------|---------|
| P0 | 替换 ASR 为 Qwen3-ASR，实现方言识别 | 0.5 天 | 30 秒内让老板"哇"一下 |
| P0 | 接入 Qwen-Omni-Realtime 端到端链路 + 前端开关 | 1-2 天 | 全双工+情绪共鸣，代差级震撼 |
| P1 | 前端"技能进化引擎"透视面板 UI | 1 天 | 可成长技能的可视化，概念落地 |
| P1 | VLM 视觉理解场景（路牌+鬼探头） | 0.5-1 天 | "第三只眼"概念，差异化亮点 |
| P2 | 万相数字人（老板形象）集成 | 1-2 天 | 视觉冲击力，但非核心功能 |
| P2 | 模拟时间触发 + 联网新闻聚合 | 1 天 | 可成长技能的完整闭环 |

**建议总工期**：**5-7 个工作日**可完成全部场景的开发与调试。如果时间紧张，优先完成 P0 级任务（方言识别 + 端到端链路），仅需 2 天即可形成一个极具冲击力的最小可演示版本。

## 六、 向老板汇报的展示策略

**开场白建议**（30 秒）：

> "今天我不讲 PPT，不讲架构图。我直接让您体验一下，未来的智能座舱和您现在车上的语音助手，到底有什么区别。"

**演示节奏建议**：

第一幕（方言秒懂）用 1 分钟快速建立信任——"连方言都能听懂"。第二幕（全双工情感交流）用 2 分钟制造核心震撼——"它像一个活人"。第三幕（第三只眼）用 2 分钟展示差异化——"它能看懂真实世界"。第四幕（可成长技能）用 3 分钟收尾升华——"它会越用越聪明"。

**关键原则**：

每一幕之间不要停下来解释技术，让老板沉浸在连续的体验中。技术细节留到老板主动追问时再回答。如果老板问"这个怎么实现的"，指向侧边的"技能透视面板"或"Omni 引擎开关"，用可视化代替口述。
