# SmartAgent4 v0.6 老板演示脚本

## 演示目标

展示 SmartAgent4 作为**车机座舱多代理智能助手**的核心能力：
1. **多代理架构**：根据用户意图智能分发任务
2. **场景记忆**：学习并复述用户的专属场景习惯
3. **个性化体验**：记住用户偏好并持续进化
4. **虚拟人交互**：AIRI 状态反馈提升交互感

---

## 一、开场 (30 秒)

> "大家好，今天演示的是 SmartAgent4 v0.6，一个面向车机座舱的多代理智能助手。
>
> 它和普通聊天机器人最大的不同在于：**后台是 Supervisor 架构，会根据用户意图把任务分发给不同领域的 Agent**。
>
> 比如：导航、娱乐、办公、生活服务、文件管理和通用记忆。
>
> 这次我们还补了 **AIRI 虚拟人状态反馈**，所以你能看到它什么时候在听、什么时候在思考、什么时候在说话。"

## 三、核心讲解词

### Step 1：多代理架构 (1 分钟)

> "首先看一下后台架构。SmartAgent4 采用 **Supervisor 模式**：
>
> - 用户输入进来后，Supervisor 先做**意图分类**（这里我们用了相似度纠偏 + LLM 兜底的四级链路，准确率很高）
> - 然后根据意图把任务分发给对应的 Agent：导航、音乐、新闻、办公、生活服务、文件管理等等
> - 每个 Agent 有自己的工具集和 Prompt，专注自己的领域
> - 最后 Supervisor 汇总结果，返回给用户
>
> 这样做的好处是：**模块化、可扩展、每个 Agent 可以独立优化**。"

### Step 2：虚拟人交互 (30 秒)

> "看右边的虚拟人 AIRI。它会实时反馈系统状态：
> - **听**：用户说话时，AIRI 会做出倾听姿态
> - **思考**：系统处理时，AIRI 会做出思考动作
> - **说话**：系统回复时，AIRI 会做出说话表情和口型同步
>
> 这样用户能更清楚地感受到交互过程，提升了产品的**可信度和沉浸感**。"

### Step 3：意图分类与多代理分发 (1 分钟)

**演示话术 1-3：**

> "现在我们来演示多代理分发。我先问一个天气问题。"
>
> *[用户输入 "你好，今天天气怎么样？"]*
>
> "系统识别这是一个 **GeneralAgent 的任务**（通用对话），所以它调用天气工具返回了结果。"
>
> *[用户输入 "帮我播放周杰伦的《说好不哭》"]*
>
> "这次识别为 **MultimediaAgent 的任务**（多媒体娱乐），系统调用音乐搜索工具，找到歌曲并播放。"
>
> *[用户输入 "从天安门到颐和园怎么走？"]*
>
> "这是 **NavigationAgent 的任务**（导航出行），系统调用高德地图 API 规划路线。"
>
> **讲解要点**：
> - 同一个系统，根据意图自动分发给不同 Agent
> - 每个 Agent 有专属工具集
> - 用户无需指定"用哪个功能"，系统自动理解意图

### Step 4：记忆与个性化 (1.5 分钟)

**演示话术 4-6：**

> "现在我们重点演示**可成长能力**。我先告诉系统我的偏好。"
>
> *[用户输入 "我喜欢听科技和 AI 新闻"]*
>
> "系统会主动把这条信息存入**长期记忆**。这不是简单的标签，而是**可更新的用户画像**。"
>
> *[用户输入 "给我推荐几条今天值得看的新闻"]*
>
> "注意：这次我没有重复说'推荐科技新闻'，但系统会从**长期记忆里召回**刚才的偏好，所以推荐的都是科技和 AI 新闻。"
>
> *[用户输入 "我最近不想看科技新闻了，多给我推点体育类的吧"]*
>
> "系统**修正了记忆**，下次推荐就会是体育类新闻。"
>
> **讲解要点**：
> - 系统不仅能回答问题，还能**主动记住用户偏好**
> - 记忆是**持续更新**的，不是一次性标签
> - 用户无需重复说相同的偏好，系统会自动应用

### Step 5：场景流程记忆（新功能，重点讲解）(2 分钟)

**演示话术 7-8：**

> "最后我要重点演示的是**场景流程记忆**。这是 v0.6 新增的能力。"
>
> *[用户输入 "我中午一般在车上睡觉，帮我把空调调到 24 度，关闭大灯，再放点白噪音，以后这就叫午睡模式"]*
>
> "系统执行了这一系列动作，并提示：**'午睡模式已保存到场景记忆'**。"
>
> "这里的关键是：系统不仅记住了**单个偏好**（比如'喜欢 24 度'），而是把**一整个复杂的动作序列**打包成了一个专属场景。"
>
> *[用户输入 "开启午睡模式"]*
>
> "现在我只需要说一句'开启午睡模式'，系统就会：
> 1. **召回**这个场景的完整动作清单（空调 24 度、关大灯、白噪音）
> 2. **复述**给用户确认：'我要为你执行：空调调到 24 度、关闭大灯、播放白噪音，是否确认？'
> 3. 等待用户**确认后再执行**
>
> 这样既**懂用户**，又**保证了车控安全**——不会因为一句模糊的指令就乱动车控。"
>
> **讲解要点**：
> - **场景记忆 ≠ 静态偏好**：它是复杂的动作序列
> - **召回 + 确认 + 执行**：三步闭环，安全可靠
> - **可扩展**：用户可以定义无限多个专属场景（晨间模式、夜间模式、运动模式等）

## 七、常见问题与回答

**Q: 这和 ChatGPT 有什么区别？**

> A: ChatGPT 是通用对话模型，SmartAgent4 是**多代理架构**。我们的优势是：
> - 每个领域有专属 Agent，工具集专业化
> - 用户意图自动分发，无需手动选择功能
> - **场景记忆**能学习用户的复杂习惯，不仅是聊天
> - 集成车机生态（导航、音乐、办公等），不是通用模型

**Q: 场景记忆和普通记忆有什么区别？**

> A: 
> - **普通记忆**：记住用户说过什么（"我喜欢科技新闻"）
> - **场景记忆**：记住用户的**动作序列**（"午睡模式 = 空调 24 度 + 关大灯 + 白噪音"），下次可以一键触发
> - 场景记忆还有**执行前确认**，保证安全

**Q: 本地有 ASR 和 TTS 吗？**

> A: 目前用的是云端 ASR（DashScope）和 TTS（Emotions-System）。我们有本地方案的设计文档（Faster-Whisper + Piper），可以在下个版本落地。本地模式会提供"在线/离线"切换，用户可以根据网络环境选择。

**Q: 这个系统能接入真实车控吗？**

> A: 完全可以。目前演示用的是 Mock 工具（模拟空调、大灯等）。生产环境只需要把这些 Mock 工具替换成真实的车控 API 即可。系统架构已经为此预留了扩展点。

## 十、应急预案

**如果某个功能失败：**

1. **保持镇定**，继续讲解原理
2. **快速跳过**该功能，进行下一个话术
3. **事后排查**：查看后端日志 `/tmp/smartagent4.log`
4. **备选方案**：准备截图或录屏作为 backup

**常见问题排查：**

| 问题 | 排查方法 |
| :--- | :--- |
| 系统无响应 | 检查 3000 端口是否监听：`netstat -tuln \| grep :3000` |
| API 调用失败 | 检查环境变量是否正确：`echo $DASHSCOPE_API_KEY` |
| 虚拟人不动 | 检查浏览器控制台是否有 JS 错误 |
| 音乐播放失败 | 检查网易云 MCP 连接：查看日志中 "Connected to 网易云音乐" |
